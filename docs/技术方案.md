# 技术方案

本文说明 sensitive3d 各环节的做法、为什么这样设计，以及可以调整的参数。代码位置用 `模块:函数` 标注。

## 0. 总体思路

倾斜摄影模型有三个特点，决定了这个方案的做法：

1. **纹理图集是碎片化的**：一个标志可能被切到多个图块里，方向也是任意的，所以**不能直接在贴图上做检测和修复**。检测和修复都在“渲染视图”里进行，再通过光栅化把每个纹理像素对应回三维表面点，这样两边可以精确互相映射。
2. **几何是“融化”在一起的**：牌面、立杆、地面常常连成一个连续曲面，所以只修纹理会留下一个鼓包。因此会删除标志的几何，再把孔洞补平。
3. **同一个标志在多级 LOD 里都有**：检测只在最精细一级进行，结果是**三维区域**；所有 LOD 都用这个三维区域来选面、选纹理像素，并从同一组修复结果中采样，所以各级是一致的。

## 1. OSGB 读写组件（`native/osgb_bridge`）

这是基于 OpenSceneGraph 的 C++ 小工具，Python 通过子进程调用它（`sensitive3d/io/osgb.py`）。

| 命令 | 作用 |
| --- | --- |
| `info <列表>` | 批量解析文件结构，**不解码贴图**。输出每个几何体的世界坐标包围盒、三角形数，以及它是否还有更精细的 LOD（`has_finer`），还有引用的子文件。用来快速扫描整个数据集。 |
| `export <in> <dir>` | 导出每个几何体（三角化后的顶点、UV、法线、颜色，以及累计的变换矩阵）和每张贴图（原始 RGB 像素）。 |
| `patch <in> <dir> <out>` | 重新读入原文件，只替换 `patch.txt` 里列出的几何体和贴图，其余节点原样保留。 |
| `build <desc> <out>` | 从文本描述生成 PagedLOD 结构的 OSGB 文件，合成数据用的就是它。 |

关键细节：

- **贴图原样保留**：组件在图像插件前面加了一层代理，读取时会把内嵌图像的原始编码字节（JPEG/PNG/DDS）记下来。写回时，没改过的贴图直接用原字节（`WriteImageHint=IncludeFile`），所以没有二次压缩损失。改过的贴图由 Python 编码成 JPEG（质量 95）后嵌入。
- 写文件时走输出流接口，避免 OSG 去输出目录里找同名图片；同时清空 PagedLOD 里的数据库路径，避免把绝对路径写进输出文件。
- 几何体在导出和回写时的遍历顺序一致，以几何体编号对应。

## 2. 自动检测（`sensitive3d/detect`）

### 2.1 候选区域（`candidates.py`）

1. 对最精细一级的贴图做 HSV 颜色分割，找出红、蓝、绿、黄四种颜色（饱和度阈值 ≥ 100，避免把蓝灰色玻璃等误判进来），再用开运算去掉零星噪点。
2. 在 UV 空间光栅化，得到每个上色纹理像素对应的三维点和所在面的法线。
3. 按 4 cm 体素做 26 邻域连通，聚成候选簇；面积 ≥ 0.03 m²、尺寸在 0.12–8 m 之间的才保留。

### 2.2 特写验证（`detector.py`、`heuristic.py`）

对每个候选簇做 PCA 平面拟合，确定朝向，然后用正交相机正对着渲染一张特写：分辨率约 360 像素，前后各留 1–1.5 m 的深度范围，以排除遮挡。在特写上判断：

- **禁令标志（红圈）**：把红色连通域的孔洞填满后，形状要接近椭圆（轴比 > 0.55，填充率约 1）；红环占比在 0.15–0.8 之间；圈内亮色像素占比 > 25%，并且有深色字符；直径在 0.25–1.8 m 之间。亮暗阈值是相对这块标志自身亮度计算的，所以背光的标志也能识别。
  - **类型判断**：圈内上下各有一个小三角，判为限高；左右各有一个小三角，判为限宽。数值通过模板匹配读取，候选值包括限速 5–120、限重 2–55t、限高 2–5.5m。如果三角和数字粘在一起，再单独取中间一条带重新识别。
- **路牌、指路标志（蓝或绿矩形）**：外接矩形填充率 > 0.78；牌内要有比底色明显更亮、饱和度更低的“字”像素，占比 3–65%，并且至少有 2 个连通块。纯蓝色的卷帘门、窗户这类不会被误判。
- **警告标志（黄三角）**：黄色区域和外扩后的黑边都要近似三角形。

### 2.3 提升到三维（`regions.py`）

把检测到的 2D 掩膜中的像素，按渲染时得到的位置图反投影成三维点，去掉深度异常的点后拟合平面，得到 `SignRegion`：中心、法线、水平轴和竖直轴，以及半宽、半高。另外还有两条过滤：

- 牌面必须足够平；
- 法线与竖直方向的夹角要足够大（交通标志都是竖着的，躺在地面上的彩色区域是路面标线）。

多个候选得到的同一标志，以及跨瓦片的同一标志，会合并为一个区域。

### 2.4 可选：学习型检测器（`yolo.py`）

可以接入任意 YOLOv5/v8 的 ONNX 模型（`--yolo`），类名可从模型元数据或同名的 `.names.txt` 读取。支持 TT100K 风格的编码：`pl*` 为限速，`ph*` 为限高，`pm*` 为限重，`pw*` 为限宽，`p*` 为其他禁令，`w*` 为警告，`i*` 为指示和指路。

接入模型后会额外渲染多方位“扫描视图”：8 个方位角，俯角 20°，按 15 m 深度分层渲染，以避免远处遮挡。这样也能找到没有明显颜色的标志。

## 3. 几何去除与补洞（`repair/geometry.py`）

1. **判断安装方式**（`analyse_region`，只在最精细一级判断一次）：
   - **墙面**：牌面背后 0.5 m 以内、牌面外围一圈有与牌面平行的表面，且面积超过外围一圈面积的 35%。
   - **立杆**：在牌面下方的竖直棱柱范围内（水平方向外扩 0.25 m），从地面以上 0.4 m 到牌底这一段有面片，而棱柱外围没有。地面高度取牌面附近朝上面片高度的中位数。
   - **其他**（例如挂在龙门架上）：只删除牌面。
2. **选出要删的面**：最精细一级按面中心落在区域内来判断。较粗的 LOD 面片很大，只删除**三个顶点都**落在稍微外扩后的标志体内的面；墙面标志在较粗的 LOD 上只修纹理，不改几何。
3. **找出新产生的孔洞边界**：先按位置把顶点焊接起来（因为 UV 接缝处顶点是重复的），再找“删除前是内部边、删除后成了边界”的边，然后追踪成闭合环。瓦片自身的外边界不会被当成孔洞。
4. **补洞**：把孔洞环投影到周围面片的平均法线平面上，用 earcut 三角化，绕向与周围面片保持一致。补丁顶点单独复制一份，这样可以拥有自己的 UV。
5. **分配纹理空间**：按周围的纹理像素尺寸，在图集中用积分图查找空闲矩形。被删面片释放出的区域可以直接用；空间不够时降低补丁分辨率，再不够就在图集底部增加行，并相应调整所有 UV。

## 4. 纹理修复（`repair/texture.py`、`repair/inpaint.py`）

### 4.1 修复视图

每个区域根据几何情况设置修复视图：

- **正面视图**：沿法线正对牌面，范围是牌面加上四周至少 0.8 m 的上下文，深度只取牌面附近很薄的一层；
- **俯视视图**：只有立杆标志才有，正对立杆底部的地面补丁。

视图在**几何已修改后的最精细层级**上渲染。需要补全的掩膜包括：补丁面、落在标志区域内的残留纹理像素，再外扩约 3 cm。

### 4.2 图像补全

- **默认方法 `auto`**：多尺度 EM / PatchMatch 补全（Wexler 等方法）。图像金字塔会一直缩小到孔洞只剩几个像素厚，这样在最粗的一层就能看到全局结构；之后每一层都用 PatchMatch 搜索最近邻块，重叠的块加权投票取平均。最细一层再混入一部分原始匹配像素，恢复颗粒感，最后做环带颜色融合，保证光照连续。补全用的样本块全部来自周围真实纹理。
- `telea`：OpenCV 快速平滑填充，很小的孔洞默认也用它。
- `lama`：接入 LaMa ONNX 模型（`--lama` 或环境变量 `S3D_LAMA_ONNX`），适合大面积的复杂背景。

### 4.3 写回所有 LOD

对每个文件的每个几何体，“目标纹理像素”包括两部分：补丁面的全部纹理像素，以及落在标志区域内的纹理像素。较粗的 LOD 会把这个区域按该级纹理像素尺寸的 2 倍外扩。

每个目标纹理像素先在三维中投影到修复视图，然后：

- 选朝向最正的那个视图；
- 要求深度一致（最精细一级容差 0.12 m，较粗 LOD 为 0.6 m）；
- 如果没有正对的视图，第二轮放宽到接近侧面的视图（用于牌边、粗糙 LOD 上的斜面）；
- 仍然没有视图能看到的纹理像素，在纹理空间用 Telea 补齐。

另外有两步收尾：

- **图集边缘填充**：双线性采样会读到图块外一圈的填充像素，所以把已修复像素旁边、不属于任何面的像素，填成最近的已修复颜色。
- **清除被删面片原来占用的纹理**：这些区域里还留着标志的图像。即使没有面再引用它们，也要覆盖掉，保证输出文件中不残留敏感内容。

## 5. 预览与复检

- 每个标志生成“处理前 / 处理后”的斜视截图，以及一块局部 GLB。整个场景的 GLB 会选取三角形数在预算内（默认 40 万）的最精细一层 LOD，供网页三维对比。
- 复检会在修复后的最精细层级上，对各个区域附近重新跑一遍检测。如果仍检测到标志，会写入报告的 `residual_detections` 并在网页上提示。

## 6. 参数一览（`PipelineConfig`）

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `detection.categories` | 全部 | 要去除的类别 |
| `detection.min_score` | 0.55 | 检测置信度阈值 |
| `detection.yolo_model` | 无 | 可选 YOLO ONNX 模型 |
| `geometry.plate_margin` | 0.05 m | 牌面在平面内的外扩 |
| `geometry.pole_margin` | 0.25 m | 立杆搜索棱柱的水平外扩 |
| `geometry.remove_poles` | True | 是否同时删除立杆 |
| `remove_geometry` | True | 关闭后只修纹理 |
| `texture.method` | auto | `auto` / `telea` / `ns` / `lama` |
| `texture.context` | 0.8 m | 修复视图四周的上下文范围 |
| `texture.residual_margin` | 0.06 m | 残留纹理像素的外扩 |

在网页上，以 JSON 形式提交的选项会原样传给 `PipelineConfig.from_dict`。
