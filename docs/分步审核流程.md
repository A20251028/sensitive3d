# 分步审核流程

网页和命令行使用同一套流程。原始数据始终只读，所有输出都写到独立的目录。

```
导入检查 → 原始预览 → 只检测 → 人工审核 → 执行修复 → 下载
 scan.json   overview    detection.json  review.json  repair.json   result.zip
```

| 步骤 | 做什么 | 写什么 | 会不会改模型 |
| --- | --- | --- | --- |
| 导入检查 | 复制工作副本（忽略 `._*` / `.DS_Store` / `__MACOSX`）；扫描结构：PagedLOD 引用图、缺失引用、多父节点、引用环、无法到达的文件、读取失败的文件、贴图问题；记录全部输入文件的 SHA-256 | `scan.json`、`input_manifest.json` | 否 |
| 原始预览 | 选取三角形数在预算内的最精细一层 LOD，生成整体预览。预览前先按贴图解码量检查内存预算；预览时缩小贴图不能代替这项检查 | `previews/overview_before.glb` | 否 |
| 只检测 | 在最精细一层 LOD 上检测，记录每个候选的来源：瓦片、文件、LOD、特写相机、2D 框与掩膜、2D→3D 映射统计、安装方式及其置信度 | `detection.json`、`evidence/` | 否 |
| 人工审核 | 逐个决定去除或保留、选择操作（仅纹理 / 删几何）、外扩范围，并设置保护区域 | `review.json` | 否 |
| 执行修复 | 只执行审核决定。每个输出文件都要回读校验；仅纹理的文件要证明几何和 UV 没有变化；核对保护区域、图集残留和输入哈希 | `repair.json`、输出目录 | 只改输出副本 |
| 下载 | 打包修复后的数据和全部报告 | `result.zip` | 否 |

导入检查出现阻断性问题时（读取失败、缺失引用、引用环、缺贴图），**修复会被拒绝**。阻断问题仍允许执行只检测，以便排查。

## 候选状态

- **可自动（auto）**：置信度不低于自动阈值（默认 0.85）、2D→3D 映射成功、安装方式判断为高置信、类别在去除范围内。
- **待审核（review）**：只要有一项不满足就是待审核。原因写在 `review_reasons` 里。待审核的候选**默认不处理**，自动模式（`process` 或网页上的 auto 选项）也不会处理。

几条硬性规则：

- 映射失败（位置只是临时估计）的候选，既不能删几何，也不能修纹理。
- 安装方式未知的候选，不能删几何。
- 置信度是检测器的打分，**不是准确率**。

## review.json

```json
{
  "decisions": [
    {"id": 0, "accept": true,  "operation": "geometry"},
    {"id": 1, "accept": true,  "operation": "texture", "margin": 0.05},
    {"id": 2, "accept": false}
  ],
  "protected": [
    {"name": "店招 (非目标)", "min": [10.0, 5.0, 0.0], "max": [12.0, 6.0, 4.0]}
  ]
}
```

- `operation`
  - `geometry`：删除牌面（立杆标志还会删除立杆），补平孔洞，再修复纹理。
  - `texture`：只修复纹理，几何和 UV 保持字节级不变，修复后会回读验证。
- `margin`：在牌面平面内外扩的范围，单位米，可以为负。
- `protected`：保护区域，是坐标系中轴对齐的包围盒。盒内的面不会被删除，纹理像素不会被重绘；修复后还会逐一对比。JPEG 重新编码会带来轻微噪声，所以只有较大的像素差异才算“有变化”。

命令行生成审核模板：`sensitive3d review-template work/detection.json -o work/review.json`。

## 命令行

```bash
sensitive3d scan    INPUT --work W                       # 导入检查
sensitive3d detect  INPUT --work W --diagnostics         # 只检测 (+ 被拒颜色候选的特写与原因)
# 编辑 W/review.template.json 另存为 W/review.json
sensitive3d repair  INPUT OUTPUT --work W --review W/review.json
```

资源限制（所有命令都可用）：

- `--max-seconds`：时间上限。
- `--max-memory-mb`：内存上限。
- `--max-decoded-mb`：一次解码贴图的总量上限，在读取之前检查。
- `--bridge-timeout`：单次 OSGB 读写的超时。

达到限制后流程会停止，已有的证据会写进报告，并标记 `stopped`。

## 报告里的结论怎么读

| 结论 | 依据 |
| --- | --- |
| 解析成功 | `scan.json`：可读文件数 = 文件总数，并且 `blocking_errors` 为空 |
| 流程运行成功 | `repair.json`：没有 `stopped`，所有修改文件的 `readback.ok` 为真 |
| 检测候选 | `detection.json` 的 `counts`：只是候选数量，不等于识别准确 |
| 视觉验收通过 | **只能人工判断**：对照同一相机的前后图、多视角、各级 LOD |
| 真实数据验收 | 按 `docs/真实数据验证.md` 逐项完成后才能声明 |

没有独立的人工标注（漏检的分母未知）时，`detection.json` 中的 recall / precision / F1 保持 `null`。修复后的复检（`residual_detections`）只是辅助手段，结果为 0 **不代表**没有残留。
